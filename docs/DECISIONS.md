# DECISIONS

**무엇을 왜 정했고 무엇을 버렸는가.** 현재 유효한 결정을 위에, 검토하고 버린 선택지를 아래에 둔다. 결론만 적고 실험 과정은 적지 않는다.

각 항목은 한두 문장이다. 근거는 판단이 갈릴 때 필요한 것만 적는다. 결정을 바꾸면 기존 항목을 맨 아래 **버린 것**으로 옮기고 한 줄로 줄인다.

# 현재 유효한 결정

## 수집

| 결정 | 근거 |
|---|---|
| 후보는 **헤드라인 통독**으로 만든다. 검색으로 만들지 않는다 | 검색은 검색어가 결과를 정한다. 후보에 없으면 순위를 어떻게 매겨도 실릴 수 없다 |
| **날짜를 지정해 받을 수 있는 소스**만 뼈대로 쓴다 | 대상 주 7일을 정확히 덮어야 한다. 일반 뉴스 RSS는 최신 몇십 건뿐이라 주말치만 들어온다. 발행 빈도가 낮은 뉴스룸 RSS만 예외다 |
| 국내는 **네이버 뉴스 랭킹**, 주요 매체 15곳 | 날짜별·언론사별 아카이브라 회고와 검증이 된다. 종합일간지 8곳, 지상파와 보도채널 5곳, 통신사 2곳 |
| 해외는 **Wikipedia Current events**를 뼈대로, **The Guardian** 피드를 보탠다 | Wikipedia는 날짜별에 분류와 출처까지 있고 매체 편향이 없다. 경제·기업이 약해 Guardian으로 메운다 |
| AI는 **뉴스룸 1차 출처 7곳**과 **Hacker News** 날짜별 프런트 | 뉴스룸은 수치가 정확하고, HN이 뉴스룸에 없는 업계 반응과 비판을 잡는다 |
| 국내 사안은 **한국어 원문**을 우선한다 | 번역을 거치지 않아 정확하고 영문판에 없는 사안이 많다 |
| 사실은 **원문 대조**로만 확정한다 | 검색 결과 요약은 생성된 텍스트다 |
| 반복도는 **`rank-topics.mjs`로 기계가 먼저 뽑는다** | 셀 대상을 직접 고르면 후보를 전수로 모은 의미가 없어진다. 무엇을 셀지 데이터가 정하게 한다 |
| 선정 후 **커버리지 검사**를 반드시 돌린다 | 상위 빈도 중 반영 안 된 낱말을 기계가 짚어 준다. 사람의 기억에 기대지 않는 마지막 관문이다 |
| 국내와 해외는 도구로 측정하고, **AI 는 목록 전체를 읽는다** | AI 풀은 200여 건으로 작고 고유명사가 두 단어로 쪼개져 빈도가 흩어진다. 같은 기준을 다른 방법으로 지킨다 |

## 선별

| 결정 | 근거 |
|---|---|
| 순위 1번은 **그 주에 얼마나 크게 다뤄졌는가** | 주간 정리의 1번은 그 주의 가장 큰 뉴스여야 한다. 헤드라인 목록에서 반복도를 세어 측정한다 |
| 이어서 되돌리기 어려움 → 영향의 범위와 깊이 → 축적 가치 → 독자 근접성 | 인명 피해와 집행된 결정이 검토·발언보다 무겁다 |
| **'많이 본'과 '많이 보도된'은 다르다** | 랭킹은 클릭 기준이라 재정·정책 기사가 불리하다. 랭킹은 후보 발굴용이고 순위는 위 기준으로 매긴다 |
| **분야를 고르게 배분하지 않는다** | 억지로 나누면 5위권 밖 사안이 3위 자리를 차지한다 |
| **건수는 15건 고정.** 부족하면 출처 개수를 양보한다 | 주차끼리 비교가 되어야 분기호와 연간호가 성립한다 |
| **도입 문단은 맨 마지막에** 쓴다 | 먼저 쓰면 그 주제에 맞춰 다섯 건을 고르게 된다 |
| 도입 문단은 **사건 이름으로** 쓴다. 구성 설명을 쓰지 않는다 | "다섯 건의 성격이 서로 다르다"는 사건을 하나도 알려 주지 않는다. 규칙이 그렇게 쓰는 것을 허용해서 2026-W35 도입 셋이 전부 그렇게 나왔다 |
| **문체는 평이하게.** 비유를 기본값으로 쓰지 않는다 | 읽는 사람은 인상이 아니라 사실을 알고 싶어 한다 |
| 주간호는 **그 주에 알 수 있었던 것만** 담는다 | 결말을 알고 쓰면 그 주의 기록이 아니게 된다. 주차 비교가 성립하고 분기·연간이 후행 정보에 오염되지 않으려면 시점을 한정해야 한다 |

## 발행과 형식

| 결정 | 근거 |
|---|---|
| **월요일 오전 8시(KST)** 발행, 주 경계는 **ISO 8601 주** | ISO 주가 닫힌 직후이며 금요일 미국 발표까지 포함된다. 표준 주차 표기를 쓰면 시점이 모호해지지 않는다 |
| 저장소는 **public**, Pages 소스는 **GitHub Actions** | 무료 계정은 public에서만 Pages가 발행된다. 빌드를 직접 소유해야 실패 로그를 보고 다른 호스팅으로 옮길 수 있다 |
| 분야별 건수는 **본문에서 센다**. 프론트매터에 적지 않는다 | 선언값과 본문이 어긋나도 아무도 모른다. 실제로 화면 두 곳이 다른 건수를 표시했다 |
| 주간 실행 절차는 `RUNBOOK_WEEKLY.md`, 분기는 `RUNBOOK_QUARTERLY.md` | 정리본은 수집도 원문 대조도 없어 절차가 갈린다. 파일 이름으로 구분한다 |
| 원본은 **마크다운** | 분기호와 연간호가 파싱 없이 읽는다. 매주 HTML을 손으로 쓰면 레이아웃과 인덱스가 흐트러진다 |
| 주간호 위의 단위는 **분기호와 연간호** 둘이다 | 한 달은 60~75건이라 아직 뉴스 묶음이고 추세가 노이즈와 구분되지 않는다. 한 분기는 약 195건이다 |
| 분기는 **13주**씩 끊는다. 53주인 해의 4분기는 14주다 | 주 단위로 끊으면 모든 주간호가 정확히 한 분기에만 속한다. 달력 분기로 끊으면 경계 주를 쪼개거나 두 번 세야 한다. ISO 8601 은 분기를 정의하지 않으므로 이것은 이 저장소의 규약이다 |
| 분기호는 **방금 발행한 주차가 분기말일 때** 주간 실행에 이어서 만든다 | W13 주간호는 W14 월요일에 발행된다. "오늘이 W13인가"로 판정하면 분기의 마지막 입력이 갖춰지기 전에 돈다 |
| 연간호는 **네 분기호만** 읽어 만든다 | 분기호가 이미 추세를 뽑은 결과다. 52주를 다시 읽으면 분기호가 한 일을 되풀이한다 |
| 분기호와 연간호는 **별도 페이지**로 낸다 | 성격이 다른 글이다. 목록에서는 같은 분기 안에 두되 카드 모양으로 구분한다 |
| 분기호는 **흐름 5 + 단발 5 = 10건 고정**이다 | 주간호 15건 고정과 같은 이유다. 분기끼리 비교가 되어야 연간이 성립하고, 독자가 길이를 예측한다. 발행된 3주차에서 2주 이상 걸친 흐름이 이미 6개 나와 공급 부족이 아니라 잘라내는 쪽이 문제다 |
| 흐름은 **2주 이상** 걸친 사안이다. 1주짜리는 단발이다 | 기계로 셀 수 있는 경계가 필요하다. 근거 주차의 개수가 그대로 판정값이 된다 |
| 다섯을 채울 때 양보하는 것은 **흐름이 걸친 주차 수**다 | 주간호가 출처 개수를 양보하는 자리와 같다. 강도는 근거 주차 목록이 그대로 드러내므로 따로 표기하지 않는다 |
| 흐름은 **통독으로 묶는다**. 빈도 도구는 빠뜨림 확인에만 쓴다 | 주간호 제목은 이미 선별·중복 제거를 거친 195건이라 상위 토큰이 일반어로 흩어진다. 실측에서 `공개·미국·장관`이 나왔다. 항목이 적을 때 전체를 읽는 것은 AI 분야에서 이미 택한 방법이다 |
| 분기호의 **축은 주제**다. 국내·해외·AI 를 가로지른다 | 한 사안이 국내와 해외에 나뉘어 실리는 일이 잦다. 분야 축을 유지하면 그런 흐름이 셋으로 쪼개진다 |
| 분기호의 근거는 **주간호 항목으로 링크**한다 | 원 기사 링크는 주간호 안에 이미 있다. 독자가 맥락을 본 뒤 내려갈 수 있고, 링크 생존을 분기호가 다시 떠안지 않는다 |
| 분기호가 아는 범위는 **그 분기의 주간호까지**다 | 분기 안에서는 결말을 알고 쓰지만 분기 밖은 보지 않는다. 그래야 분기호도 그 분기의 기록으로 남는다 |
| 주간호 항목에 `<분야>-<번호>` **앵커**를 단다 | 분기호가 개별 항목을 가리켜야 한다. `home`·`world`·`ai` 는 빌드가 이미 쓰던 이름이다 |
| 탭은 **기간**이다. 연도 칩과 분기 칩을 한 줄에 두고 `연간` 을 뒤에 붙인다. 탭마다 주소가 따로 있고 자바스크립트를 쓰지 않는다 | 종류로 나누면 주간호 목록이 해마다 길어지기만 한다. 연말에 27개, 이듬해엔 80개다. 기간으로 나누면 한 화면이 13~14건에서 멈추고, 분기호가 자기 근거인 주간호 옆에 놓인다 |
| 연간호는 연도 칩이 아니라 **분기 옆 칩**으로 간다 | 연도 칩에 걸면 "그 해를 고른다"와 "연간호를 연다"가 충돌한다. 연도가 둘 이상이 되는 날 고를 방법이 없어진다 |
| 한 분기 목록은 **분기호가 맨 위**, 그 아래 주간호 최신순이다 | 분기호가 그 분기에서 가장 나중에 나온 발행물이고, 13주를 다 읽지 않아도 되게 해 주는 요약이다. 맨 아래면 스크롤 13번 뒤라 아무도 못 본다 |
| 홈은 **가장 나중 분기**와 같은 화면이다 | 처음 온 사람이 최신을 본다. 대신 분기가 바뀐 첫 주에는 홈에 주간호가 한 건뿐이다. 바로 옆 탭에 직전 분기가 차 있으므로 받아들인다 |
| 내용이 없는 분기는 **탭에 나오지 않는다** | 2026년은 3분기부터 시작한다. 빈 Q1·Q2 를 달아 두면 미완성으로 보인다 |
| 발행물 주소는 **종류별 경로 그대로** 둔다. 새로 생기는 것은 기간 목록뿐이다 | 바꾸면 이미 나간 주소가 깨지고 분기호의 근거 링크를 전부 다시 써야 한다 |
| 단발 항목에도 **앵커를 준다** | 연간호의 근거가 분기호 단발을 가리킨다. 흐름에만 앵커가 있어서 그 링크가 깨졌다 |
| `site/` 는 **커밋하지 않는다** | Pages 소스가 Actions 라 저장소의 산출물은 배포에 쓰이지 않는다. CSS 가 페이지마다 인라인이라 한 글자만 고쳐도 전 파일이 다시 쓰인다(104주 기준 105개 전부). 원본과 산출물이 어긋날 위험도 사라진다 |
| 라이선스는 **저장소 전체에 CC BY-NC-SA 4.0** 하나다 | 코드를 따로 MIT 로 열 이유가 없었다. 어차피 상업적 사용을 막을 것이고, 저작권자 본인의 재사용은 라이선스와 무관하다. 지킬 것은 선별과 배열이며, 근거는 저작권법 제6조 편집저작물이다. 제7조 5호가 사실의 전달에 불과한 시사보도를 보호에서 빼므로 사실 자체는 지킬 수 없다 |
| 라이선스 문서에 **설명을 쓰지 않는다** | 무슨 라이선스인지만 밝히면 읽는 사람이 찾아본다. 인용한 기사의 권리가 이 라이선스 밖이라는 고지만 남긴다 |
| **사람 검수를 주장하지 않는다** | 사실이 아니다. 사람의 역할은 파이프라인 관리이며 그 한계를 사이트에 밝힌다 |
| 본문에는 **매체를 쓰지 않는다**. 출처 줄에만 둔다 | 모든 문장이 보도에서 온 것이라, 일부에만 매체를 붙이면 나머지가 출처 없는 말처럼 보인다 |
| 발행물에 **만드는 쪽의 용어와 측정값을 쓰지 않는다** | 독자는 이 저장소를 모른다. `(대상 주 밖이다)` 를 읽으면 무슨 말인지 몰라 걸리고, 헤드라인 반복 횟수는 무엇을 실을지 정하려고 우리가 잰 값이지 그 사안이 왜 중요한지에 대한 답이 아니다 |
| 시점이 대상 주 밖이라는 것은 **날짜를 적어서** 알린다 | 독자에게 필요한 정보는 언제 있었던 일인가뿐이다. 날짜를 쓰면 그것으로 끝난다 |
| 사건 날짜는 **현지 날짜**로 쓴다. 주 경계에 걸리면 KST 로 판정한다 | 기사에 적힌 날짜 그대로라 대조가 쉽다. KST 로 환산하면 해외 사안이 기사와 하루씩 어긋나 보인다 |
| 본문을 **날짜순으로 늘어놓지 않는다** | 시점은 `날짜` 필드가 이미 답해서 같은 정보를 두 번 쓰게 된다. 문단 다섯 개가 날짜로 시작하면 다 읽고 나서야 핵심을 알게 된다. 한 항목에 사안이 여럿이면 날짜가 아니라 사안으로 묶는다 |
| 출처끼리는 **`/` 로 나눈다** | 가운뎃점은 매체 이름 안에도 쓰여 경계가 흐려진다 |
| 출처는 **매체 이름과 링크만** 쓴다. 같은 매체가 두 번 나올 때의 구분 키워드와 위키백과 링크의 `매체 (Wikipedia)` 표기만 예외 | 부연을 달면 줄이 길어지고 항목마다 형식이 달라진다. 두 예외는 부연이 아니라 링크를 구별하고 대상을 맞게 밝히는 데 필요하다 |
| 본문은 **18px · 한 줄 34자 · 자간 -0.02em · 왼쪽 정렬 · 어절 단위 줄바꿈**(`word-break:keep-all`) | 국내 신문 본문이 모두 이 조합이다. 중앙 `keep-all`, 한겨레 `normal`, 경향 `break-word` 이며 셋 다 18px · 580~592px · 왼쪽 정렬이고 양쪽 정렬은 쓰지 않는다. 줄 끝에 평균 1.2자가 비는 대신 단어가 쪼개지지 않는다 |
| 항목 안의 모든 블록을 같은 좌우 끝에 맞춘다 | 블록마다 폭이 다르면 눈이 매 줄 시작점을 다시 찾는다 |
| 긴 본문은 **문단으로 나눠 쓴다** | 한 덩어리는 갈래가 안 보인다. 마크다운 항목 안의 빈 줄을 문단 경계로 쓴다 |
| 한 문서가 다른 문서의 항목을 **열거하지 않는다**. 가리키기만 한다 | 검사는 늘어나는데 열거는 안 따라온다. 주간 런북이 점검 문서의 검사 아홉 개 중 여섯 개만 적고 있었고, 빠진 셋은 직전 주 사고를 막으려고 더한 것이었다 |
| 발행 뒤 **배포된 페이지를 받아 확인한다** | CI 성공은 빌드가 끝났다는 뜻이다. 페이지가 비었거나 목록에 안 걸려도 CI 는 녹색이다 |
| 막힌 매체는 **출처 줄에도 쓰지 않는다** | 읽지 못한 원문을 근거로 내세우는 것이 된다. 2026-W36 이 CNBC·Axios·Washington Post·France 24·Bloomberg·VentureBeat 를 14번 인용했고, 그 매체에만 있던 사실을 받아지는 원문으로 확인할 수 없어 뺐다 |
| 표에 없는 매체는 **먼저 7절 표에 넣고** 쓴다 | 출처 검사는 표에 없는 이름을 발표 주체로 본다. NBC News 가 그렇게 분류되어, 주요 매체가 없는 항목이 순서 검사와 함께 빠져나갔다 |
| 주간호마다 **실행 기록**을 `data/runs/` 에 남기고 `/stats/` 에 공개한다. 발행하는 세션이 푸시 직전에 자기 대화 기록으로 계산한다 | 정기 실행 세션에는 세션 조회 도구가 없다. 대화 기록 계산은 조회 값과 마지막 호출 하나만큼만 다르다(2026-09-26 대조). 비용은 API 정가 환산이고, 주간 사용량(%)은 어디서도 얻을 수 없다 |

## 아직 정하지 않은 것

- 주간호 항목에 태그를 달 것인가. 흐름을 통독으로 묶기로 해서 지금은 필요가 없다. 기계적 집계가 필요해질 때 다시 본다.
- 반기 단위를 둘 것인가. 분기와 연간을 돌려 보고 사이가 비는지 확인한 뒤에 정한다.
- 본문 수치를 출처 원문과 자동으로 대조하는 검사를 빌드에 넣을 것인가.
- 거시 지표의 추이를 따로 기록할 것인가. 큰 경제 뉴스는 국내 5건으로 올라오지만(2026-W36은 5건 중 3건), 크게 보도되지 않은 주의 지표 변화는 보도량 기준 선별로 잡히지 않는다. 분야를 늘려서는 해결되지 않는 문제다.

## 선별

| 버린 것 | 왜 |
|---|---|
| 경제·부동산을 **별도 분야로 추가**(한 호 25건) | 공급이 없다. 네이버 많이 본 기사 주당 525건 중 경제어 포함 1%, 부동산어 1~3%(6~17건)이고, 3주 동안 상위 10위에 든 것은 1건뿐이었다. 5건을 중요도로 채울 수 없어 매주 억지로 채우게 된다 |
| 경제를 **별도 탭이나 프로젝트로 분리** | 수집·원문 대조·집필을 한 벌 더 돌려야 해 주간 실행 비용이 2배가 되고, 분기호와 연간호 대상이 둘로 갈린다 |
| 복수 매체 보도를 중요도 지표로 쓰기 | 검증이 쉽다는 뜻이지 더 중요하다는 뜻이 아니다. 게이트와 순위를 분리했다 |
| 기준 미달이면 덜 싣기 | 주차 간 비교가 깨진다. 건수를 고정하고 양보 대상을 출처 개수로 바꿨다 |

## 발행

| 버린 것 | 왜 |
|---|---|
| 월간호 | 한 달은 표본이 적어 추세가 보이지 않고, ISO 주와 달력 월이 어긋나 한 주간호가 두 달에 걸친다. 분기로 대체했다 |
| Pages Branch 소스 + Jekyll | 폴더가 고정되고 `_` 로 시작하는 파일이 무시된다. 설정이 GitHub Pages 전용이라 이식성이 없다 |
| 토요일·일요일·금요일 발행 | 주 경계가 잘리거나 미국 금요일 발표를 못 담는다 |
| "사람이 검수합니다" 표기 | 사실이 아니었다 |
| 출처 표기 `(보조 매체)` · `(단일 매체)` · `(1차 출처)` 와 링크 라벨의 부연 | 매체 이름이 이미 목록에 나와 있어 같은 것을 두 번 말한다. 선별 기준 자체는 8절에 그대로 남는다 |
| 본문 **양쪽 정렬**(`text-align:justify`) | 줄 끝은 맞지만 어절 사이가 늘어나 자간이 들쭉날쭉해진다. 줄 끝은 음절 단위 줄바꿈으로 맞추는 편이 낫다 |
| `word-break:normal` 로 음절 줄바꿈 기대 | Chromium 에서 한글은 `keep-all` 과 동작이 같다. 음절 단위로 끊는 값은 `break-all` 뿐이다 |
| 종류별 탭(주간호·분기호·연간호)과 내용 없는 종류 숨김 | 주간호 목록이 해마다 길어지기만 한다. 기간 탭으로 바꿨고 숨김 규칙은 분기 단위로 옮겼다 |
| **음절 단위 줄바꿈**(`break-all`)과 그에 딸린 숫자·영문 보호용 `<span>` | 줄 끝은 거의 맞지만(빈칸 평균 0.5자) 단어가 줄을 넘어 쪼개져 간행물로 보이지 않는다. 네이버는 쓰지만 신문사 본지는 한 곳도 쓰지 않는다 |
