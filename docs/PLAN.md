### 로컬(맥) 백필 — 로컬 세션이 먼저 할 일

사용자는 W27~W34 백필을 로컬 맥에서 돌린다. 클라우드와 사용 한도가 따로 잡혀서다. 로컬 Claude Code 는 `AGENTS.md` 를 자동으로 읽지 않으므로, 로컬 세션은 `AGENTS.md` 와 이 문서를 먼저 읽고 아래를 순서대로 한다. 1은 에이전트가 직접 하고, 2와 3은 문구를 만들어 사용자 승인을 받는다.

1. **대화 기록 형식을 확인한다.** 클라우드에서 확인한 계산이 로컬에서도 같은 기준이 되려면 대화 기록 형식이 같아야 한다. 이 세션의 기록에서 사용량이 있는 줄마다 캐시 쓰기가 5분과 1시간으로 나뉘어 있는지 센다.

   ```bash
   f=$(ls -t ~/.claude/projects/*/*.jsonl | head -1)
   node -e 'let a=0,b=0;for(const l of require("fs").readFileSync(process.argv[1],"utf8").split("\n")){try{const u=JSON.parse(l).message?.usage;if(u){a++;if(u.cache_creation&&"ephemeral_1h_input_tokens" in u.cache_creation)b++}}catch{}}console.log(`사용량 ${a}줄, 5분·1시간 구분 ${b}줄`)' "$f"
   node scripts/record-run.mjs 2099-W01 --transcript "$f"; rm -f data/runs/2099-W01.json
   ```

   - 두 수가 같고 0보다 크면 형식이 같다. `record-run.mjs` 가 비용을 내면 통과다.
   - 구분 줄이 모자라면 멈추고 사용자에게 알린다. 지금 스크립트는 구분이 없는 줄을 5분 요금으로 계산해 비용을 낮게 적는다. 조용히 틀리는 경우라 스크립트가 멈추도록 고치자고 제안해 둔 상태다.

2. **맥에서 날짜 계산.** 런북 1절의 `date -d` 는 GNU 문법이라 맥 기본 `date` 에서 돌지 않는다. 백필은 주차를 직접 주므로 월요일·일요일만 구하면 된다. 맥에서 되는 방법을 실험해 보고 런북에 넣을 문구를 사용자에게 제안한다.

3. **백필 발행 절차.** 런북에 백필을 `main` 에 발행하는 절차가 없다. 지금 절차대로 주차를 직접 지정하면 1절의 시험 경로로 빠져 `claude/` 브랜치에 올라간다. 아래를 담은 문구를 사용자에게 제안하고 승인받는다.
   - 주차를 지정해 2절부터 13절까지 그대로 한다
   - 14절 기록은 `--backfill` 을 붙인다
   - `main` 에 발행한다
   - 한 호를 한 세션에서 만든다. 세션 전체가 곧 그 호의 기록이 된다

4. **그다음 백필.** W27 부터 한 호에 한 세션씩 돌린다. 7절의 막힌 매체는 로컬에서 열려도 쓰지 않는다. 호끼리 같은 기준이어야 한다.

- 빈도 도구는 입력의 성격을 탄다. `rank-topics.mjs` 를 주간호 제목에 돌리면 상위 토큰이 `공개·미국·장관` 같은 일반어로 나온다. 날것의 중복 많은 헤드라인 525건에 맞춰 만든 것이라, 이미 선별을 거친 195건에는 선별용으로 안 맞는다. 도구를 다른 데 쓰기 전에 그 입력으로 한 번 돌려 본다.
- 수집 풀에 없다고 보도가 없는 것은 아니다. 물가 기사가 네이버 많이 본 랭킹에 없어 보조 매체만으로 실었는데, 언론사별 날짜 목록에는 주요 매체 다섯 곳에 있었다. 찾는 방법은 `RUNBOOK_WEEKLY.md` 8절에 있다.
- 읽기는 프록시가 익명으로 주지만 푸시는 루틴에 저장소가 등록되어 있어야 한다. 읽기와 쓰기가 여기서 갈린다.
- 수동 발화에 딸려 보낸 지시는 세션이 실행하지 않는다. 페이로드는 데이터로 취급된다. 세션에 시킬 일은 런북이나 프롬프트에 적어야 한다.
- 같은 사실을 두고 세션마다 보고가 엇갈릴 수 있다. GitHub MCP 가 있느냐를 두고 한 세션은 없다고, 다른 세션은 쓰고 있다고 했다. 세션의 자기 보고는 근거 하나일 뿐이다.
- 냉시작 세션이 확인할 수 없는 과거를 추측으로 메웠다. 첫 발화에서 "정기 실행이 월요일에 이미 W37 을 발행한 뒤"라고 적었는데 W37 은 수동 발행이었다. 결론은 맞았고 근거가 틀렸다.
- 소스가 범위 밖 요청에 오류 대신 엉뚱한 데이터를 주기도 한다. 네이버는 아카이브 밖 날짜에 오늘 랭킹을 돌려줬다. 받아진 것이 요청한 것인지 확인하는 장치가 있어야 한다.
- 검사를 만들면 문서의 빈틈이 드러난다. 출처 순서 검사가 7절 매체 표에 Axios 와 Gulf News 가 빠져 있던 것을 찾아냈다. 규칙만 두고 검사를 안 만들면 이런 것이 조용히 쌓인다.
- 네이버 랭킹은 EUC-KR 이고 Node 의 `fetch` 는 403 을 받아 `curl` 로 받는다.
- 실행 환경은 UTC 이며 회수되면 사라진다. 남길 것은 반드시 커밋한다.
- 세션에서 저장소 생성과 Pages 활성화는 불가능하다. 사용자가 직접 처리했다.
