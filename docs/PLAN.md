2026-09-27 과거 주차 13개를 실제 실행과 같은 다섯 소스로 받아 비교했다(W38·W30·W27·W20·W10·W02, 2025년 W40·W26·W10, 2021~2024년 W26).

- **국내·해외·HN 은 2021년까지 줄지 않는다.** 네이버 랭킹은 날마다 15곳이 찼고, 위키와 가디언 날짜 목록도 날짜별로 받아진다. 가디언 URL 은 2024년 표본에서 `/world/article/<연도>/` 형식이라 세는 패턴에 주의한다.
- **원문 생존율도 날짜로 떨어지지 않는다.** 표본에서 국내는 모든 주차 100%, 해외는 AP 를 빼면 2022년까지 거의 다 받아졌다. 실패는 원래 막힌 AP(7절 표)와 라이브블로그뿐이었다.
- **품질이 갈리는 곳은 AI 다.**

  - TechCrunch AI 기사는 주당 2022년 26건, 2021년 14건으로 분야 자체가 작았다.
- **하한은 2020년 11월 중순이다.** 네이버 랭킹 아카이브가 거기까지다(런북 2절).

## AI 순위의 측정값

AI 는 4절 1순위("얼마나 크게 다뤄졌는가")를 셀 목록이 없다. 뉴스룸은 회사마다 한 번 발표하고, HN 은 개발자 관심사로 치우친다. 2026-09-27 W38 로 시험했다.

- 테크 매체 날짜 목록이 받아진다(로컬 맥). TechCrunch 는 WordPress API 로 날짜·AI 카테고리 필터가 되고 2025년도 나온다. The Verge 는 월별 사이트맵에 AI 섹션 URL 이 있지만 날짜가 수정 시각이다. Ars Technica 는 날짜 페이지가 있지만 사이드바 인기 기사가 매일 섞인다. Techmeme 은 과거 날짜가 여전히 403 이다.
- W38 한 주에 세 매체 AI 기사가 144건이었다. 감속·자율 규제 논쟁이 20건 넘게 반복됐고 발행 1번과 맞는다. AI 에이전트 해킹 사고는 약 8건인데 빠졌고, 5번 Gemini 3.8 Live 는 세 매체에 0건이고 HN 프런트에만 있었다.
- HN 은 감속·규제 논쟁을 한 건도 잡지 못했다.
- 로컬 백필 세션은 "techcrunch 2026/08/19 AI" 같은 날짜 검색으로 이 목록을 손으로 만들었다. 로컬 호에 TechCrunch 가 많은 이유로 보인다.
- Anthropic 뉴스룸은 최근 글 10여 건만 보여 줘서 과거 주차 백필에서는 늘 비어 나온다. RSS 는 404 이고 사이트맵에도 뉴스 날짜가 없다(2026-09-27 W30 백필). 발표 목록도 같은 방향 안에서 정한다
- 클라우드에서도 받아진다(2026-09-27 대화형 세션). TechCrunch API 는 curl·Node fetch 모두 되고 7일 연속 요청도 막히지 않았다. The Verge 사이트맵과 Ars 날짜 페이지는 **curl 만** 되고 Node fetch 는 환경의 외부 접속 정책이 403(`Blocked by egress policy`)으로 막는다. 수집기는 `read-article.mjs` 처럼 curl 로 받아야 한다. 원문 추출은 세 매체 모두 되지만 본문 앞에 배너·메뉴가 섞인다. TechCrunch URL 의 날짜는 미국 현지 날짜라 UTC 발행일과 하루 어긋날 수 있다
- 2026-09-27 `aimedia` 소스(TechCrunch·The Verge)로 넣었다. 런북 2절이 매체 수로 세게 한다. 출처 검사도 AI 항목에 AI 주요 매체나 1차 출처가 없으면 짚는다. W32·W35·W37·W38 의 AI 5건이 걸린다

## 해보고 알게 된 것

- 빈도 도구는 입력의 성격을 탄다. `rank-topics.mjs` 를 주간호 제목에 돌리면 상위 토큰이 `공개·미국·장관` 같은 일반어로 나온다. 날것의 중복 많은 헤드라인 525건에 맞춰 만든 것이라, 이미 선별을 거친 195건에는 선별용으로 안 맞는다. 도구를 다른 데 쓰기 전에 그 입력으로 한 번 돌려 본다.
- 수집 풀에 없다고 보도가 없는 것은 아니다. 물가 기사가 네이버 많이 본 랭킹에 없어 보조 매체만으로 실었는데, 언론사별 날짜 목록에는 주요 매체 다섯 곳에 있었다. 찾는 방법은 `RUNBOOK_WEEKLY.md` 8절에 있다.
- 읽기는 프록시가 익명으로 주지만 푸시는 루틴에 저장소가 등록되어 있어야 한다. 읽기와 쓰기가 여기서 갈린다.
- 수동 발화에 딸려 보낸 지시는 세션이 실행하지 않는다. 페이로드는 데이터로 취급된다. 세션에 시킬 일은 런북이나 프롬프트에 적어야 한다.
- 같은 사실을 두고 세션마다 보고가 엇갈릴 수 있다. GitHub MCP 가 있느냐를 두고 한 세션은 없다고, 다른 세션은 쓰고 있다고 했다. 세션의 자기 보고는 근거 하나일 뿐이다.
- 냉시작 세션이 확인할 수 없는 과거를 추측으로 메웠다. 첫 발화에서 "정기 실행이 월요일에 이미 W37 을 발행한 뒤"라고 적었는데 W37 은 수동 발행이었다. 결론은 맞았고 근거가 틀렸다.
- 소스가 범위 밖 요청에 오류 대신 엉뚱한 데이터를 주기도 한다. 네이버는 아카이브 밖 날짜에 오늘 랭킹을 돌려줬다. 받아진 것이 요청한 것인지 확인하는 장치가 있어야 한다.
- 검사를 만들면 문서의 빈틈이 드러난다. 출처 순서 검사가 7절 매체 표에 Axios 와 Gulf News 가 빠져 있던 것을 찾아냈다. 규칙만 두고 검사를 안 만들면 이런 것이 조용히 쌓인다.
- 원문만 검사하면 렌더링에서 생긴 문제를 놓친다. W32 는 "6억~12억 … 12억~25억" 의 두 물결표 사이가 취소선으로 발행됐고, 검사와 검토가 모두 마크다운만 봐서 지나갔다. 통계 페이지를 만든 커밋은 번호 배지의 클래스 이름을 바꿔 색 박스를 지웠는데 CI 는 녹색이었다. 둘 다 이제 빌드가 막는다.
- 권한 설정은 `ask` 가 `allow` 보다 우선한다. 어느 설정 파일에서 오든 그렇다. 저장소 `.claude/settings.json` 에 커밋·푸시를 허용해도 사용자 전역 `ask` 가 있으면 로컬에서는 계속 묻는다.
- 막힌 매체는 환경마다 다르다. 로컬 맥에서는 CNBC 가 열리고 클라우드에서는 막힌다. 7절 표는 정기 실행 환경 기준이다.
- 사용량 한도를 비용으로 환산하면 5시간 한도가 약 $40($38~43), 7일 한도가 약 $400($270~810)이다. W31 로컬 백필 전후 `/usage` 사용률 차이(5시간 8→28%, 7일 70→72%)를 세션 전체 비용으로 나눴다. 7일은 정수 % 오차 때문에 범위가 넓다.
- 모델을 바꾸면 비용이 크게 달라진다. W38 은 `claude-opus-5` 로 $15.05 였고, `claude-opus-5-5` 로 돈 백필은 $4~7 이다. 비용의 대부분인 캐시 읽기 단가가 2.5배 차이 난다.
- 2026년 수집에는 경계가 없다. W1·W3·W5·W9·W17·W35 를 재 보니 국내는 어디서나 525건/7일이고 위키도 7일 모두 있다. 국내 원문도 W1·W17·W35 에서 12건씩 모두 받아졌다. AI 건수는 그 주의 발표량을 따라 W1 1건, W5 24건, W35 26건이다.
- 실행 기록의 `session` 은 CLI 세션 ID 이고 대화 기록 파일 이름과 같다. claude.ai 세션 ID(`cse_…`·`session_…`, 커밋의 `Claude-Session:` 링크)와는 다른 값이다. 클라우드도 `CLAUDE_CODE_SESSION_ID`·`CLAUDE_CODE_REMOTE=true` 를 두는 것을 2026-09-27 대화형 세션 두 곳에서 확인했다. 정기 실행의 claude.ai 세션은 루틴 실행 목록에서 시각으로 찾는다.
- 오래 이어진 세션은 대화 기록이 불완전하다. 19일 이어진 클라우드 세션은 대화 기록 계산이 공식 비용의 42% 였다. 한 호를 짧은 한 세션에서 만드는 이유가 하나 더 있다.
- 네이버 랭킹은 EUC-KR 이고 Node 의 `fetch` 는 403 을 받아 `curl` 로 받는다.
- 실행 환경은 UTC 이며 회수되면 사라진다. 남길 것은 반드시 커밋한다.
- 세션에서 저장소 생성과 Pages 활성화는 불가능하다. 사용자가 직접 처리했다.
