# 작업 체크리스트

**지금 무엇을 하는 중인가.** 진행 중인 일과 아직 결론이 안 난 것을 담는다. 끝난 항목은 지운다.

## 다음 세션 시작 순서

**데드라인을 기준으로 삼지 않는다.** 정기 실행은 이미 끝까지 도는 것을 확인했고, 남은 문제는 무엇을 어떤 형식으로 내느냐다.

사용자가 정한 순서다. 앞의 것이 끝나야 다음으로 간다. 다만 2026-09-26 사용자가 3번 백필을 1·2번과 나란히 먼저 시작했다.

1. **문서를 읽고 개선한다.** 사용자가 `docs/` 를 정독하고 수정 제안을 낸다. 그것을 반영한다. `AGENTS.md` 는 한 번 돌았다.
2. **그때 쓴 기준을 검사로 남긴다.** 사용자가 무엇을 보고 고치자고 했는지가 곧 기준이다. 그 기준이 다음에도 지켜지도록 `QUALITY_CHECKS.md` 에 항목으로 넣는다.
3. **3분기를 백필한다.** 아래 "3분기 백필".
4. **분기호를 발행한다.** 2026-Q3 이며, 백필이 끝난 온전한 13주가 입력이다. 9월 28일 W39 가 발행되어도 분기 런북 1절이 2026-Q3 에서 멈추게 해 두었다.

## 사용자가 직접 해야 하는 것

- [ ] **백필이 끝나면 전역 `ask` 를 되돌린다.** 로컬 백필 동안만 `~/.claude/settings.json` 의 `ask` 에서 `"Bash(git commit*)"`, `"Bash(git push*)"` 를 뺐다. 에이전트는 이 파일을 고칠 수 없다(auto mode 가 자기 권한 수정으로 막는다)

## 3분기 백필

3분기는 W27~W39 다. W31~W34 가 끝났고 **W27~W30 이 남았다.** W35~W38 은 이미 있고 W39 는 9월 28일 정기 실행이 채운다.

로컬 맥에서 한 호에 새 세션 하나씩, auto mode 로 돌린다. 백필 세션은 이 문서를 읽지 않는다. 필요한 규칙은 모두 `AGENTS.md` 와 주간 런북에 있고, 정기 실행과 같은 조건이어야 한다.

```
2026-W30 을 백필해 줘. 주간 실행 절차를 2026-W30 을 대상 주차로 처음부터 끝까지 따라.
계획 승인은 필요 없고, main 에 커밋하고 푸시하는 것도 미리 승인한다. 중간에 멈추지 말고 발행과 배포 확인까지 끝내.
```

끝난 호는 세션 기록과 배포 페이지로 확인한다. 출처마다 원문을 받은 흔적, `QUALITY_CHECKS.md` 3절, 막힌 매체 인용, 배포 페이지의 서식이다.

| 호 | 시간 | 기록 비용 | 세션 전체 | 헤드라인 | 비고 |
|---|---|---|---|---|---|
| W34 | 15분 | $6.26 | $6.72 | 908 | 커밋·푸시에서 승인 대기(전역 `ask`) |
| W33 | 12분 | $5.78 | $6.18 | 871 | |
| W32 | 10분 | $4.36 | $4.63 | 862 | 취소선 사고, 고침 |
| W31 | 13분 | $6.94 | $8.07 | 924 | 세션 전체는 `/cost` |

- [ ] **기록 뒤 호출 몫을 정한다.** 기록은 푸시 전에 하므로 푸시와 배포 확인이 빠진다. 런북 14절은 "한 호에 1% 미만"이라고 하는데 로컬 백필에서는 세션 전체의 6~14% 였다. 문구를 고칠지 기록 시점을 옮길지 사용자와 정한다
- [ ] **사용량 한도와 비용의 비율을 잰다.** 백필 전후 `/usage` 의 사용률 차이를 세션 전체 비용으로 나눈다. 직전 5시간 동안 쓴 것이 없어야 창에서 빠져나가는 양이 없다. 그 사이 다른 세션은 쓰지 않는다(계정 공유). 사용률은 정수 %라 ±1%p 오차가 있다
  - W31: 5시간 8→28%, 7일 70→72%. 5시간 한도 약 $40($38~43), 7일 한도 약 $400($270~810)
  - 7일은 한 호로는 오차가 커서 여러 호를 이어 돌린 누적으로 다시 잰다

해외 원문 생존율과 후행 지식이 새는지는 아직 재지 않았다. 해외는 위키 Current events 가 출처를 매체 이름으로만 줘서 표본을 못 뽑았다. 후행 지식은 발행일 필터로 막을 수 있는 부분과 없는 부분을 가른다. 1·2분기는 3분기 결과를 보고 정한다.

- [ ] 세션 조회 도구가 있는 클라우드 대화형 세션에서 W39 세션을 조회해 비용이 맞는지. W38 로 대화 기록 계산이 조회 값과 맞는 것은 확인했다

## 문서 점검 때 같이 볼 것

문서끼리, 또는 검사와 실제가 어긋난 곳을 모았다. 고치지 않고 적어만 둔다.

- 상투 표현 목록이 두 벌이다. 주간 런북 10절과 `QUALITY_CHECKS.md` 3.3 의 검사 낱말이 일부만 겹친다. 가르다·맞물리다·굳어지다 같은 10절의 말은 검사에 없다.
- 주간 런북의 4절 순위와 5절 게이트는 번호와 실행 순서가 반대다. 5절은 "순위를 매기기 전에 거른다"로 시작하고 6절의 순서도 게이트가 먼저다.
- 분기 런북 5절이 "시점은 주차로 쓴다"고 하고 예시가 "W27 에 …"다. 외부 독자는 W27 이 언제인지 모른다.
- `AGENTS.md` 디렉터리 표의 `scripts/` 설명이 빌드와 원문 추출만 적는다. 헤드라인 수집·빈도·출처 검사·실행 기록이 빠졌다. 빌드 명령 주석도 주간호만 적는다.
- `DECISIONS.md` 의 "선별 기준 자체는 8절에 그대로 남는다"가 어느 문서의 8절인지 밝히지 않는다. 같은 문서의 "통신사 2곳"은 연합뉴스TV 를 통신사로 센 것이다.
- 7절 표의 The Verge · The Information · Semafor 는 원문이 받아지는지 아직 재지 않았다.
- 순위 표현 검사(3.3.2)가 "차례로"·"341차례"처럼 순서와 횟수를 잡는다. 시점 검사(3.4)는 연도를 보지 않아 "2023년 10월 7일"을 주 이후로 잡는다. 둘 다 오탐이다.

## 해보고 알게 된 것

- 빈도 도구는 입력의 성격을 탄다. `rank-topics.mjs` 를 주간호 제목에 돌리면 상위 토큰이 `공개·미국·장관` 같은 일반어로 나온다. 날것의 중복 많은 헤드라인 525건에 맞춰 만든 것이라, 이미 선별을 거친 195건에는 선별용으로 안 맞는다. 도구를 다른 데 쓰기 전에 그 입력으로 한 번 돌려 본다.
- 수집 풀에 없다고 보도가 없는 것은 아니다. 물가 기사가 네이버 많이 본 랭킹에 없어 보조 매체만으로 실었는데, 언론사별 날짜 목록에는 주요 매체 다섯 곳에 있었다. 찾는 방법은 `RUNBOOK_WEEKLY.md` 8절에 있다.
- 읽기는 프록시가 익명으로 주지만 푸시는 루틴에 저장소가 등록되어 있어야 한다. 읽기와 쓰기가 여기서 갈린다.
- 수동 발화에 딸려 보낸 지시는 세션이 실행하지 않는다. 페이로드는 데이터로 취급된다. 세션에 시킬 일은 런북이나 프롬프트에 적어야 한다.
- 같은 사실을 두고 세션마다 보고가 엇갈릴 수 있다. GitHub MCP 가 있느냐를 두고 한 세션은 없다고, 다른 세션은 쓰고 있다고 했다. 세션의 자기 보고는 근거 하나일 뿐이다.
- 냉시작 세션이 확인할 수 없는 과거를 추측으로 메웠다. 첫 발화에서 "정기 실행이 월요일에 이미 W37 을 발행한 뒤"라고 적었는데 W37 은 수동 발행이었다. 결론은 맞았고 근거가 틀렸다.
- 소스가 범위 밖 요청에 오류 대신 엉뚱한 데이터를 주기도 한다. 네이버는 아카이브 밖 날짜에 오늘 랭킹을 돌려줬다. 받아진 것이 요청한 것인지 확인하는 장치가 있어야 한다.
- 검사를 만들면 문서의 빈틈이 드러난다. 출처 순서 검사가 7절 매체 표에 Axios 와 Gulf News 가 빠져 있던 것을 찾아냈다. 규칙만 두고 검사를 안 만들면 이런 것이 조용히 쌓인다.
- 원문만 검사하면 렌더링에서 생긴 문제를 놓친다. W32 는 "6억~12억 … 12억~25억" 의 두 물결표 사이가 취소선으로 발행됐고, 검사와 검토가 모두 마크다운만 봐서 지나갔다. 통계 페이지를 만든 커밋은 번호 배지의 클래스 이름을 바꿔 색 박스를 지웠는데 CI 는 녹색이었다. 둘 다 이제 빌드가 막는다.
- 권한 설정은 `ask` 가 `allow` 보다 우선한다. 어느 설정 파일에서 오든 그렇다. 저장소 `.claude/settings.json` 에 커밋·푸시를 허용해도 사용자 전역 `ask` 가 있으면 로컬에서는 계속 묻는다.
- 막힌 매체는 환경마다 다르다. 로컬 맥에서는 CNBC 가 열리고 클라우드에서는 막힌다. 7절 표는 정기 실행 환경 기준이다.
- 모델을 바꾸면 비용이 크게 달라진다. W38 은 `claude-opus-5` 로 $15.05 였고, `claude-opus-5-5` 로 돈 백필은 $4~7 이다. 비용의 대부분인 캐시 읽기 단가가 2.5배 차이 난다.
- 2026년 수집에는 경계가 없다. W1·W3·W5·W9·W17·W35 를 재 보니 국내는 어디서나 525건/7일이고 위키도 7일 모두 있다. 국내 원문도 W1·W17·W35 에서 12건씩 모두 받아졌다. AI 건수는 그 주의 발표량을 따라 W1 1건, W5 24건, W35 26건이다.
- 네이버 랭킹은 EUC-KR 이고 Node 의 `fetch` 는 403 을 받아 `curl` 로 받는다.
- 실행 환경은 UTC 이며 회수되면 사라진다. 남길 것은 반드시 커밋한다.
- 세션에서 저장소 생성과 Pages 활성화는 불가능하다. 사용자가 직접 처리했다.
