## 사용자가 정할 것 — 방문자와 알리기 (2026-09-29 요청)

지금 실제 독자는 사용자 한 명이다. 크게 홍보하기보다, 관심 있는 사람이 찾아보면 찾을 수 있게 하는 것이 목표다. 제안한 순서는 방문자 통계 → 검색 등록·RSS → GeekNews Show GN 한 번이다. "사람을 어떻게 모았나"에 잰 숫자로 답하려면 재는 것이 먼저다.

- [ ] **방문자 통계.** 모든 페이지에 스크립트 한 줄을 넣는다. 후보는 구글 애널리틱스(무료, 머문 시간 있음, 쿠키라 고지 필요)와 쿠키 없는 도구(GoatCounter·Cloudflare Web Analytics·Umami). 머문 시간 제공과 무료 범위는 고를 때 확인한다. 개발자 독자는 광고 차단기를 많이 써서 실제보다 적게 센다
- [ ] **검색 노출.** 없는 것은 sitemap.xml(영문 페이지 포함), canonical, og:url, RSS 다. 구글 Search Console 과 네이버 서치어드바이저에 사이트맵을 낸다
  - `robots.txt` 와 사파리 북마크 아이콘은 도메인 뿌리(`yg-moon.github.io`)에만 둘 수 있다. 뿌리 저장소를 만들지 검색 등록 때 같이 정한다
- [ ] **알리는 곳과 신원.** GeekNews Show GN 은 한 번 올리는 곳이라 목표에 맞는다. Threads·새 인스타 계정은 계속 올려야 효과가 나서 맞지 않는다. 사이트 주소와 저장소가 개인 계정 아래라 신원을 가리려면 계정이나 조직을 옮겨야 한다. 포트폴리오가 목적이면 드러나는 편이 낫다(2026-09-29 제안, 검토 중)
  - AI 가 쓴 글에 대한 반감은 결과물보다 만드는 방식(규칙·검사·비용 공개)을 앞세우면 덜하다

## 장기 과제 — 내용 정확성

사람은 개별 항목을 검증하지 않는다. 다음은 그 한계를 좁히는 일이다. 링크 생존(배포 단계)과 수치 대조(발행 전 경고)는 있다.

- [ ] 발행일 범위 검사(`QUALITY_CHECKS.md` 3.4)를 스크립트로 만든다. 지금은 발행 세션이 명령을 붙여 넣어 돌린다
- [ ] 복수 출처 간 수치 불일치 탐지. `check-figures.mjs` 가 항목의 출처를 이미 다 받으므로 거기에 붙일 수 있다
- [ ] 렌더링된 글자를 원문 글자와 비교하는 검사. 지금은 취소선만 막는다
- [ ] 독자가 오류를 알릴 경로와 정정 이력

## 해보고 알게 된 것

- 권한 설정은 `ask` 가 `allow` 보다 우선한다. 어느 설정 파일에서 오든 그렇다. 저장소 `.claude/settings.json` 에 커밋·푸시를 허용해도 사용자 전역 `ask` 가 있으면 로컬에서는 계속 묻는다.
- 사용량 한도를 비용으로 환산하면 5시간 한도가 약 $40($38~43), 7일 한도가 약 $400($270~810)이다. W31 로컬 백필 전후 `/usage` 사용률 차이(5시간 8→28%, 7일 70→72%)를 세션 전체 비용으로 나눴다. 7일은 정수 % 오차 때문에 범위가 넓다.
- 모델을 바꾸면 비용이 크게 달라진다. W38 은 `claude-opus-5` 로 $15.05 였고, `claude-opus-5-5` 로 돈 백필은 $4~7 이다. 비용의 대부분인 캐시 읽기 단가가 2.5배 차이 난다.
