# RUNBOOK_QUARTERLY

**분기호 실행 절차.** 대상 분기를 정하는 것부터 발행까지의 절차를 담는다. 분기 루틴([`ROUTINE_QUARTERLY.md`](ROUTINE_QUARTERLY.md))이 매주 월요일 이 문서로 시작하고, 대부분의 주는 1절에서 끝난다.

## 0. 사전 읽기

- [`../AGENTS.md`](../AGENTS.md) 의 **문서 작성 규칙**.
- [`INTENT.md`](INTENT.md) 의 **품질 기준**.
- [`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 의 **4절 순위**와 **10절 문체**. 분기호가 그대로 쓴다.

## 주간호와의 차이

- **수집이 없다.** 입력은 이미 발행된 주간호 파일이다. 헤드라인을 받지도, 기사 원문을 대조하지도 않는다.
- **분기 전체를 아는 상태로 쓴다.** 주간호는 그 주에 알 수 있었던 것만 담지만(9절), 분기호는 W27 을 다루면서 W39 에 벌어진 일을 안다. 추세를 보는 것이 목적이므로 그것이 본체다.
- **분기 밖은 보지 않는다.** 아는 범위는 그 분기의 주간호까지다. 분기 안에서 결말이 나지 않은 사안은 **"분기가 끝난 시점까지 진행 중"** 으로 쓰고 끝낸다. 지난 분기호에 같은 흐름이 있으면 그 항목으로 가는 링크 하나만 단다(5절).
- **비용이 훨씬 작다.** 주간 실행 비용의 대부분은 수집과 원문 대조다.

## 1. 대상 분기 확정

분기는 13주씩 끊는다. 4분기만 그 해의 마지막 주까지이며, 53주인 해에는 14주다.

| 분기 | 어느 주차까지인가 |
|---|---|
| Q1 | W13 까지 |
| Q2 | W26 까지 |
| Q3 | W39 까지 |
| Q4 | 그 해의 마지막 주까지 (52 또는 53) |

```bash
SUN=$(TZ=Asia/Seoul date -d 'last sunday' '+%Y-%m-%d')   # 직전에 끝난 주의 일요일
WEEK=$(date -d "$SUN" '+%G-W%V')                          # 직전에 끝난 주
Y=${WEEK%%-*}; N=$((10#${WEEK##*-W}))
LAST=$(node -e 'const y=+process.argv[1],d=new Date(Date.UTC(y,0,1)).getUTCDay(),leap=y%4==0&&(y%100!=0||y%400==0);console.log(d==4||(leap&&d==3)?53:52)' "$Y")   # 그 해의 마지막 ISO 주차
if   [ $N -eq $LAST ]; then Q=$Y-Q4
elif [ $N -ge 39 ];    then Q=$Y-Q3
elif [ $N -ge 26 ];    then Q=$Y-Q2
elif [ $N -ge 13 ];    then Q=$Y-Q1
else                        Q=$((Y-1))-Q4
fi                                                        # 가장 최근에 끝난 분기
```

- **분기를 지정받으면** 그 분기를 대상으로 삼는다. 손으로 발행하거나 다시 낼 때다.
- **지정이 없으면** 위의 `Q`, 가장 최근에 끝난 분기가 대상이다.
- 아래 둘 중 하나면 아무것도 하지 않고 종료한다.
  - `content/quarter/<Y>-Q<분기>.md` 가 이미 있다.
  - 그 분기 마지막 주차의 주간호가 아직 없다. 주간 실행이 늦어진 것이므로 다음 주 월요일에 다시 본다.
- **2026-Q3 은 지정 없이는 만들지 않는다.** 백필한 13주를 입력으로 손으로 낸다. 2026-Q3 을 낸 뒤 이 줄을 지운다.

## 2. 입력

`content/week/` 의 그 분기 주간호 13개(또는 14개)를 **전부 읽는다.** 사이트의 HTML 이 아니라 마크다운 원본을 읽는다. 195건에 약 17만 토큰이라 한 번에 읽힌다.

주간호가 빠진 주차가 있으면 **그 사실을 본문에 밝힌다.** 없는 주를 있는 것처럼 다루지 않는다.

## 3. 흐름 — 분야마다 셋

분기호는 주간호와 같이 국내·해외·AI 로 나누고, 분야마다 흐름 셋과 단발 둘을 싣는다.

**흐름은 2주 이상에 걸쳐 전개된 하나의 사안이다.** 같은 당사자의 일이 앞 사건의 결과로 이어져야 한다. 후티의 사우디 해상 봉쇄 선언 → 홍해 연안 장악 → 리야드 공격이 한 흐름이다. "중동 정세"나 "AI 모델 경쟁" 같은 분야·주제 범주는 흐름이 아니다. 범주로 묶으면 여러 주에 걸쳤다는 기준이 쉽게 부풀려진다.

- **통독으로 묶는다.** 13개를 읽고 판단으로 묶는다. 주간호 2절이 쓰는 빈도 도구는 여기서 선별용으로 쓰지 않는다. 주간호 제목은 이미 선별과 중복 제거를 거친 195건이라 상위 토큰이 일반어로 흩어진다.
- **분야는 그 사안의 항목이 가장 많이 실린 분야다.** 다른 분야에 실린 항목도 근거로 건다. 호르무즈 파병 논의가 국내에 실렸어도 미국·이란 전쟁 흐름의 근거가 된다.
- 한 주간호 항목은 흐름 하나에만 쓴다.

**순위는 주간 순위의 합으로 매긴다.** 근거 항목마다 그 주의 번호를 점수로 바꿔 더한다. 1번이 5점, 5번이 1점이다. 점수가 높은 흐름이 1번이다.

- 주간호가 이미 잰 "그 주에 얼마나 크게 다뤄졌는가"를 분기로 쌓은 값이다. 걸친 주 수만 세면 5번으로 나온 주와 1번으로 나온 주가 같아진다.
- 점수가 같으면 주간호 4절의 2~5번 기준으로 가른다. 되돌리기 어려움 → 영향의 범위와 깊이 → 축적 가치 → 독자 근접성 순이다.

**분야마다 셋을 채운다.** 모자라면 2주짜리도 싣는다. 강도는 따로 표기하지 않는다. 근거 목록이 그대로 드러내므로 독자가 보고 판단한다.

**고른 뒤 빠뜨린 것을 확인한다.** 주간호 제목을 목록으로 만들어 넘기면 반영 안 된 상위 토큰을 짚어 준다. 여기서만 도구를 쓴다.

```bash
grep -h '^### ' content/week/<그 분기 주차들>.md | sed 's/^### [0-9]*\. /- /' > /tmp/q.md
node scripts/rank-topics.mjs /tmp/q.md --covered "흐름1,흐름2,…"
```

걸린 것마다 뺀 이유를 댈 수 있어야 한다. 흐름이 아니라서 뺀 것이면 4절 후보로 넘긴다.

## 4. 단발 — 분야마다 둘

흐름에 들지 않은 그 분야의 사안에서 둘을 고른다.

- **주간 순위가 높은 것부터 본다.** 그 주 1번이었던 항목이 2번이었던 항목보다 앞선다.
- 같은 순위끼리는 주간호 4절의 2~5번 기준으로 가른다.

## 5. 항목 작성

분야마다 1~3번이 흐름, 4~5번이 단발이다.

흐름은 셋을 갖춘다.

- **제목** — 한 줄. 날짜를 넣지 않는다.
- **전개** — 분기 동안 어떻게 움직였는지 한 문단. 분기 초의 상태에서 분기 말의 상태로 무엇이 바뀌었는지가 중심이다. 매주의 사건을 차례로 늘어놓지 않는다. 시점은 "7월 초", "8월 14일"처럼 날짜로 쓴다.
- **근거** — 그 흐름을 이루는 주간호 항목으로 가는 링크다.

단발은 **제목**, 한 문장의 **무슨 일**, **근거**를 갖춘다. 무슨 일에는 해석을 붙이지 않는다.

**근거는 주간호 항목으로 건다.** 원 기사 링크는 주간호 안에 이미 있고, 독자가 맥락을 다 본 뒤에 내려갈 수 있다. 앵커는 `<분야>-<번호>` 이며 분야는 `korea`·`world`·`ai` 다. 분기호는 `/quarter/<분기>/` 에 놓이므로 주간호까지 두 단계를 올라간다. 사이트가 하위 경로로 서비스되어 절대 경로는 쓰지 않는다.

```markdown
### 1. 흐름 제목

- **전개**: 7월 초 …로 시작해 8월 중순 …로 바뀌었고 분기가 끝나는 9월 말까지 …였다.
- **근거**: [2026-Q2 해외 1](../../quarter/2026-Q2/#world-1) / [W27 해외 2](../../week/2026-W27/#world-2) / [W33 국내 1](../../week/2026-W33/#korea-1)
```

**지난 분기에서 이어진 흐름은 그 분기호 항목을 근거 맨 앞에 하나 건다.** 독자가 출발점을 따라갈 수 있게 하는 링크다. 전개에 쓰는 사실은 여전히 이 분기 주간호에서만 가져온다. 지난 분기호가 없거나 거기에 같은 흐름이 없으면 달지 않는다.

문체는 주간호 10절이 그대로 적용된다. "왜 중요한가" 칸이 따로 없는 대신 전개 문단이 그 역할을 하므로, 11절의 **판단 없는 말·근거 없는 예측·가리키는 것 없는 말** 금지가 여기에도 걸린다.

## 6. 도입 문단은 두지 않는다

분야마다 제목 바로 아래 1번 항목으로 시작한다. 사이트가 목차를 만든다. 주간호와 같다.

## 7. 콘텐츠 파일 작성

`content/quarter/<Y>-Q<분기>.md` 에 저장한다.

```markdown
---
quarter: 2026-Q3
period_start: 2026-06-29
period_end: 2026-09-27
---

## 국내

### 1. 흐름 제목

- **전개**: …
- **근거**: [W29 국내 1](../../week/2026-W29/#korea-1) / [W31 국내 1](../../week/2026-W31/#korea-1)

### 4. 단발 제목

- **무슨 일**: …
- **근거**: [W29 국내 2](../../week/2026-W29/#korea-2)

## 해외

## AI
```

- 프론트매터는 평면 `key: value` 만 쓴다. 건수는 적지 않는다.
- 섹션 제목은 `## 국내`, `## 해외`, `## AI` 셋으로 고정한다.
- 기간은 그 분기 첫 주차의 월요일부터 마지막 주차의 일요일까지다(KST).
- "이번 분기", "최근" 같은 상대 표기는 쓰지 않는다.

## 8. 점검과 발행

발행 전에 본다.

- 분야마다 흐름 3개, 단발 2개인가. 건수는 고정이다.
- 흐름마다 근거 주차가 **2개 이상**인가. 1개면 단발이다.
- 분기 밖에서 온 사실이 섞이지 않았는가.
- 근거 링크는 빌드가 검사한다. 그 분기 밖 주차나 없는 항목을 가리키면 빌드가 멈춘다.
- 주간호 10절 상투 표현이 있는가. `QUALITY_CHECKS.md` 3.3 의 명령을 대상 파일만 바꿔 돌린다.

**실행 기록을 남긴다.** 푸시 직전에 이 세션의 대화 기록으로 비용·시간·모델을 계산해 `data/runs/<Y>-Q<분기>.json` 에 쓴다. 발행물과 같은 커밋에 넣는다. 절차와 한계는 주간 런북 14절과 같다.

```bash
node scripts/record-run.mjs <Y>-Q<분기>
```

```bash
npm ci && npm run build
git add content/quarter/<Y>-Q<분기>.md data/runs/
git commit -m "Publish <Y>-Q<분기>"
git push origin main
```

- 이 저장소는 `main` 에 직접 발행한다.
- 푸시 뒤 CI 성공을 확인한다. 실패하면 로그를 읽고 원인을 남긴다.

**배포된 페이지를 받아 본다.** CI 성공은 빌드가 끝났다는 뜻이지 페이지가 제대로 나왔다는 뜻이 아니다.

```bash
SITE=https://yg-moon.github.io/ai-weekly-news
curl -s "$SITE/quarter/<Y>-Q<분기>/" -o /tmp/pub.html -w '응답: %{http_code}\n'
echo "항목: $(grep -c '<article class="item"' /tmp/pub.html)건"
echo "목록: $(curl -s "$SITE/<Y>/Q<분기>/" | grep -c "quarter/<Y>-Q<분기>/")건"
```

응답 200, 항목 15건, 목록 1건이어야 한다. 하나라도 다르면 배포가 아직 안 끝났거나 빌드가 그 분기를 빠뜨린 것이다. 잠시 뒤 다시 보고, 그래도 같으면 CI 로그를 읽는다.

## 9. 연말 연간호

대상 분기가 4분기면 분기호를 발행한 뒤 [`RUNBOOK_YEARLY.md`](RUNBOOK_YEARLY.md) 를 읽고 그 절차를 이어서 수행한다.

## 제목과 경로 규약

[`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 의 "제목과 경로 규약"에 있다. 분기호는 주간호와 별도 페이지로 나간다.

## 아직 검증되지 않은 것

- 이 절차는 한 번도 실행되지 않았다. 첫 실행은 손으로 내는 2026-Q3 이고, 분기 루틴이 스스로 내는 첫 분기는 2026-Q4 다.
- 분야마다 흐름이 셋씩 나오는지. 2026년 2·3분기 제목을 읽고 묶었을 때는 분야마다 셋 이상 나왔다.

빌드는 준비돼 있다. `content/quarter/<Y>-Q<분기>.md` 를 두면 `/quarter/<Y>-Q<분기>/` 로 나가고, 그 분기 목록(`/<Y>/Q<분기>/`) 맨 위에 놓인다. 목차, 목록의 분야별 1위, 근거 링크 검사까지 뼈대 파일로 확인했다.

8절의 배포 확인 명령은 뼈대 파일을 빌드해 로컬 서버로 돌려 본 것까지다. 실제 주소에서는 첫 분기호를 내는 날 확인한다.
