# RUNBOOK_QUARTERLY

**분기와 연간 인사이트를 어떻게 만드는가.** 대상 분기를 정하는 것부터 발행까지의 절차를 담는다. 주간 실행이 [`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 15절에서 이 문서로 넘어온다.

## 아직 정해지지 않은 것

**무엇을 싣고 어떤 형식으로 쓸지는 정하지 않았다.** 아래는 실행 조건과 입출력까지만 정한 것이다. 첫 분기가 닫히기 전에 내용 규칙을 정해 이 문서에 더한다.

## 주간과 무엇이 다른가

- **수집이 없다.** 입력은 이미 발행된 주간호 파일이다. 헤드라인을 받지도, 기사 원문을 대조하지도 않는다.
- **시점 한정이 적용되지 않는다.** 주간호는 그 주에 알 수 있었던 것만 담지만([`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 9절), 분기 인사이트는 분기 전체를 아는 상태로 쓴다. W01 을 다루면서 W13 에 벌어진 일을 알아도 된다. 추세를 보는 것이 이 문서의 목적이므로 그것이 본체다.
- **비용이 훨씬 작다.** 주간 실행 비용의 대부분은 수집과 원문 대조다.

## 1. 대상 분기 확정

분기는 13주씩 끊는다. 4분기만 그 해의 마지막 주까지이며, 53주인 해에는 14주다.

| 분기 | 주차 |
|---|---|
| Q1 | W01~W13 |
| Q2 | W14~W26 |
| Q3 | W27~W39 |
| Q4 | W40~마지막 주(52 또는 53) |

```bash
Y=${WEEK%%-*}                       # 발행한 주차의 ISO 연도
N=${WEEK##*-W}                      # 발행한 주차 번호
LAST=$(date -d "$Y-12-28" +%V)      # 그 해의 마지막 ISO 주차
```

- 대상은 **방금 발행한 주차가 속한 분기**다. 오늘 날짜로 정하지 않는다.
- `content/quarter/<Y>-Q<분기>.md` 가 이미 있으면 덮어쓰지 않고 종료한다.

## 2. 입력

`content/week/` 의 그 분기 주간호 13개(또는 14개)를 전부 읽는다. 사이트의 HTML 이 아니라 마크다운 원본을 읽는다.

주간호가 빠진 주차가 있으면 **그 사실을 인사이트 본문에 밝힌다.** 없는 주를 있는 것처럼 다루지 않는다.

## 3. 연간 인사이트

발행한 주차가 그 해의 마지막 주이면 분기 인사이트를 만든 뒤 이어서 연간을 만든다.

- 입력은 **그 해의 분기 인사이트 네 개뿐**이다. 주간호를 다시 읽지 않는다. 분기호가 이미 추세를 뽑은 결과이므로, 52주를 다시 읽으면 분기호가 한 일을 되풀이한다.
- `content/year/<Y>.md` 가 이미 있으면 덮어쓰지 않는다.

## 4. 발행

경로와 제목 규약은 [`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 의 "제목과 경로 규약"에 있다. 분기호와 연간호는 주간호와 별도 페이지로 나간다.

빌드와 푸시는 주간과 같다.

```bash
npm ci && npm run build
git add content/quarter/<Y>-Q<분기>.md
git commit -m "Publish <Y>-Q<분기>"
git push origin main
```

- 이 저장소는 `main` 에 직접 발행한다.
- 푸시 뒤 CI 성공을 확인하고 종료한다.

## 아직 검증되지 않은 것

- 이 절차는 한 번도 실행되지 않았다. 첫 분기말은 2026-W39 발행일인 2026년 9월 28일이다.
- 빌드 스크립트가 `content/quarter/` 와 `content/year/` 를 아직 읽지 않는다.
