# RUNBOOK_QUARTERLY

**분기호와 연간호를 어떻게 만드는가.** 대상 분기를 정하는 것부터 발행까지의 절차를 담는다. 주간 실행이 [`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 15절에서 이 문서로 넘어온다.

## 0. 먼저 읽는다

- [`../AGENTS.md`](../AGENTS.md) 의 **문서 작성 규칙**.
- [`INTENT.md`](INTENT.md) 의 **품질 기준**.
- [`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 의 **4절 순위**와 **10절 문체**. 분기호가 그대로 쓴다.

## 주간과 무엇이 다른가

- **수집이 없다.** 입력은 이미 발행된 주간호 파일이다. 헤드라인을 받지도, 기사 원문을 대조하지도 않는다.
- **분기 전체를 아는 상태로 쓴다.** 주간호는 그 주에 알 수 있었던 것만 담지만(9절), 분기호는 W27 을 다루면서 W39 에 벌어진 일을 안다. 추세를 보는 것이 목적이므로 그것이 본체다.
- **분기 밖은 보지 않는다.** 아는 범위는 그 분기의 주간호까지다. 분기 안에서 결말이 나지 않은 사안은 **"분기가 끝난 시점까지 진행 중"** 으로 쓰고 끝낸다.
- **비용이 훨씬 작다.** 주간 실행 비용의 대부분은 수집과 원문 대조다.

## 1. 대상 분기 확정

분기는 13주씩 끊는다. 4분기만 그 해의 마지막 주까지이며, 53주인 해에는 14주다.

| 분기 | 어느 주차까지인가 |
|---|---|
| Q1 | W13 까지 |
| Q2 | W26 까지 |
| Q3 | W39 까지 |
| Q4 | 그 해의 마지막 주까지 (52 또는 53) |

```bash
Y=${WEEK%%-*}                       # 발행한 주차의 ISO 연도
N=${WEEK##*-W}                      # 발행한 주차 번호
LAST=$(date -d "$Y-12-28" +%V)      # 그 해의 마지막 ISO 주차
```

- 대상은 **방금 발행한 주차가 속한 분기**다. 오늘 날짜로 정하지 않는다.
- `content/quarter/<Y>-Q<분기>.md` 가 이미 있으면 덮어쓰지 않고 종료한다.

## 2. 입력

`content/week/` 의 그 분기 주간호 13개(또는 14개)를 **전부 읽는다.** 사이트의 HTML 이 아니라 마크다운 원본을 읽는다. 195건에 약 17만 토큰이라 한 번에 읽힌다.

주간호가 빠진 주차가 있으면 **그 사실을 본문에 밝힌다.** 없는 주를 있는 것처럼 다루지 않는다.

## 3. 흐름 다섯 개

**흐름은 2주 이상에 걸쳐 전개된 하나의 사안이다.** 한 주차에만 나온 것은 흐름이 아니라 4절의 단발이다.

- **통독으로 묶는다.** 13개를 읽고 판단으로 묶는다. 주간호 2절이 쓰는 빈도 도구는 여기서 선별용으로 쓰지 않는다. 그 도구는 날것의 중복 많은 헤드라인 525건에 맞춰져 있고, 주간호 제목은 이미 선별과 중복 제거를 거친 195건이라 상위 토큰이 일반어로 흩어진다. 항목이 적을 때 목록 전체를 읽는 것은 주간호 2절이 AI 분야에 대해 이미 택한 방법이다.
- 분야를 가로지르는 묶음을 그대로 둔다. 국내와 해외에 나뉘어 실린 같은 사안은 한 흐름이다.

**순서는 주간호 4절 기준을 분기로 올려서 매긴다.** 앞의 것이 더 무겁다.

1. **몇 주에 걸쳤는가** — 근거 주차의 개수다. 분기에서 가장 오래 이어진 흐름이 1번이다. 주간호 1번의 "그 주에 얼마나 크게 다뤄졌는가"에 대응한다.
2. **되돌리기 어려움** — 인명 피해와 집행된 결정이 무겁다.
3. **영향의 범위와 깊이**.
4. **축적 가치** — 연간 정리에서 다시 볼 사안인가.
5. **독자 근접성** — 한국 독자의 생활·일·자산에 닿는가.

**다섯 개를 채운다.** 양보하는 것은 **흐름이 걸친 주차 수**다. 다섯 번째가 2주짜리여도 싣는다. 강도는 따로 표기하지 않는다. 근거 주차 목록이 그대로 드러내므로 독자가 보고 판단한다.

**고른 뒤 빠뜨린 것을 확인한다.** 주간호 제목을 목록으로 만들어 넘기면 반영 안 된 상위 토큰을 짚어 준다. 여기서만 도구를 쓴다.

```bash
grep -h '^### ' content/week/<그 분기 주차들>.md | sed 's/^### [0-9]*\. /- /' > /tmp/q.md
node scripts/rank-topics.mjs /tmp/q.md --covered "흐름1,흐름2,흐름3,흐름4,흐름5"
```

걸린 것마다 뺀 이유를 댈 수 있어야 한다. 단발이라 뺀 것이면 4절 후보로 넘긴다.

## 4. 단발 다섯 건

흐름에 들어가지 않았지만 그 분기에 컸던 일을 **다섯 건** 고른다. 한 주차에만 나온 사안이 대상이다.

- 순서는 3절 기준의 2~5번으로 매긴다. 1번은 흐름 전용이다.
- 한 건에 한 줄이다. 무슨 일이었는지만 쓰고 해석을 붙이지 않는다.

## 5. 항목 작성

흐름은 셋을 갖춘다.

- **제목** — 한 줄. 날짜를 넣지 않는다.
- **전개** — 분기 동안 어떻게 움직였는지 한 문단. 시점은 주차로 쓴다. 주간호 항목의 요약을 다시 늘어놓지 않는다.
- **근거** — 그 흐름을 이루는 주간호 항목으로 가는 링크다.

**근거는 주간호 항목으로 건다.** 원 기사 링크는 주간호 안에 이미 있고, 독자가 맥락을 다 본 뒤에 내려갈 수 있다. 앵커는 `<분야>-<번호>` 이며 분야는 `home`·`world`·`ai` 다. 분기호는 `/quarter/<분기>/` 에 놓이므로 주간호까지 두 단계를 올라간다. 사이트가 하위 경로로 서비스되어 절대 경로는 쓰지 않는다.

```markdown
### 1. 흐름 제목

- **전개**: W27 에 …로 시작해 W33 에 …로 바뀌었고 분기가 끝나는 시점까지 …였다.
- **근거**: [W27 해외 2](../../week/2026-W27/#world-2) / [W33 국내 1](../../week/2026-W33/#home-1)
```

단발은 한 줄이며 근거 링크 하나를 단다.

문체는 주간호 10절이 그대로 적용된다. "왜 중요한가" 칸이 따로 없는 대신 전개 문단이 그 역할을 하므로, 11절의 **판단 없는 말·근거 없는 예측·가리키는 것 없는 말** 금지가 여기에도 걸린다.

## 6. 도입 문단

맨 앞에 한 단락을 둔다. **다섯 흐름을 다 쓴 뒤에 쓴다.** 먼저 쓰면 그 주제에 맞춰 흐름을 고르게 된다. 주간호 6절과 같은 이유다.

- 이 분기가 어떤 분기였는지 한두 문장으로 쓴다.
- 공통점이 있으면 쓰고, 없으면 성격이 서로 다르다고 쓴다. 억지로 엮지 않는다.

## 7. 콘텐츠 파일 작성

`content/quarter/<Y>-Q<분기>.md` 에 저장한다.

```markdown
---
quarter: 2026-Q3
period_start: 2026-06-29
period_end: 2026-09-27
---

(이 분기가 어떤 분기였는지 한 단락)

## 흐름

### 1. 제목

- **전개**: …
- **근거**: [W27 해외 2](../../week/2026-W27/#world-2)

## 단발

- …했다. [W31 국내 4](../../week/2026-W31/#home-4)
```

- 프론트매터는 평면 `key: value` 만 쓴다. 건수는 적지 않는다.
- 섹션 제목은 `## 흐름`, `## 단발` 둘로 고정한다.
- 기간은 그 분기 첫 주차의 월요일부터 마지막 주차의 일요일까지다(KST).
- "이번 분기", "최근" 같은 상대 표기는 쓰지 않는다.

## 8. 점검과 발행

발행 전에 본다.

- 흐름 5개, 단발 5개인가. 건수는 고정이다.
- 흐름마다 근거 주차가 **2개 이상**인가. 1개면 단발이다.
- 모든 근거 링크의 주차가 그 분기 안에 있는가.
- 분기 밖에서 온 사실이 섞이지 않았는가.
- 주간호 10절 상투 표현이 있는가. `QUALITY_CHECKS.md` 3.3 의 명령을 대상 파일만 바꿔 돌린다.

```bash
npm ci && npm run build
git add content/quarter/<Y>-Q<분기>.md
git commit -m "Publish <Y>-Q<분기>"
git push origin main
```

- 이 저장소는 `main` 에 직접 발행한다.
- 푸시 뒤 CI 성공을 확인하고 종료한다.

## 9. 연간호

발행한 주차가 그 해의 마지막 주이면 분기호를 만든 뒤 이어서 연간을 만든다.

- 입력은 **그 해의 분기호 네 개뿐**이다. 주간호를 다시 읽지 않는다. 분기호가 이미 추세를 뽑은 결과이므로, 52주를 다시 읽으면 분기호가 한 일을 되풀이한다.
- 구조는 분기호와 같다. 흐름 다섯, 단발 다섯이다. 입력이 분기호이므로 근거는 분기호 항목으로 건다.
- 한 해에 걸친 흐름은 **여러 분기의 흐름이 이어진 것**이다. 한 분기에만 있던 흐름은 연간에서 단발 후보다.
- `content/year/<Y>.md` 가 이미 있으면 덮어쓰지 않는다.

## 제목과 경로 규약

[`RUNBOOK_WEEKLY.md`](RUNBOOK_WEEKLY.md) 의 "제목과 경로 규약"에 있다. 분기호와 연간호는 주간호와 별도 페이지로 나간다.

## 아직 검증되지 않은 것

- 이 절차는 한 번도 실행되지 않았다. 형식을 보려고 시험 발행을 먼저 돌린다.
- 13주에서 흐름이 실제로 다섯 개 나오는지. W35~W37 세 주차에서 2주 이상 걸친 흐름이 6개 나온 것이 근거의 전부다.

빌드는 준비돼 있다. `content/quarter/<Y>-Q<분기>.md` 를 두면 `/quarter/<Y>-Q<분기>/` 로 나가고 목록 페이지와 탭이 함께 생긴다. 뼈대 파일로 확인했다.
