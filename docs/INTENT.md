# INTENT

이 문서는 **무엇을 왜 만드는가**를 담는다. 매주 어떻게 만드는지는 [`ROUTINE.md`](ROUTINE.md)가 담당하며, 두 문서는 내용을 중복하지 않는다.

변경 빈도가 낮은 문서다. 실행 절차를 다듬는 일로는 이 문서를 건드리지 않는다.

## 대상과 범위

- 대상은 지난 한 주에 실제로 있었던 일이며, 지금 시점의 최신 속보가 아니다.
- 주의 경계는 ISO 8601 주(월요일~일요일)를 따른다.
- 분야는 국내·해외·AI 셋이며 각 5건으로 고정한다.
- 세 분야는 각각 따로 고민한다. 하나의 방식으로 뭉뚱그려 처리하지 않는다.

## 목표

- 접근 가능한 정적 사이트를 GitHub Pages로 발행하고, 모바일과 데스크톱을 모두 지원한다.
- 주간호가 쌓여 월간 인사이트가 되고, 그것이 모여 연간 트렌드로 이어지게 한다.
- 분기·반기 단위를 둘지는 아직 정하지 않았다. 주간호가 충분히 쌓인 뒤 실제 필요를 보고 결정한다.

## 품질 기준

- 공신력 있는 매체를 기반으로 한다.
- 여러 매체가 함께 보도한 사안을 우선한다.
- 중요하고 믿을 수 있는 것만 싣는다. 개수를 채우는 것보다 신뢰가 우선이다.
- 억지 부리지 않는다. 안 되는 건 안 된다고 말하고, 현재 가능한 최선을 한다.
- 한계를 감추거나 결과를 그럴듯하게 포장하지 않는다.
- 헤드라인 나열이 아니라 요약과 맥락을 함께 싣는다. "무슨 일이 있었는지"와 "왜 중요한지"가 모두 있어야 한다.

## 결과물

- 웹페이지 형태로 본다.
- 매주 새로 쌓이며 덮어쓰지 않는다. 지난 주차를 언제든 되짚어 볼 수 있어야 한다.
- 제목만 봐도 언제 내용인지 식별된다. 시점이 모호한 표기는 쓰지 않는다.
- 발행이 완료되면 푸시 알림을 받는다.

## 진행 방식

- 확정 전에 실험한다. 어디까지 가능한지 먼저 파악하고 결정한다.
- 바꾸기 전에 논의한다. 선택지와 근거를 먼저 내놓고 결정은 사용자가 한다.
- 근거는 선례에서 찾는다. 판단을 앞세우기보다 기성 관행을 확인한 결과를 우선한다.
- 수집 기준과 선별 방식은 고정이 아니라 계속 다듬어 가는 대상이다.

## 기술 제약

- 버전 관리와 되돌리기가 가능해야 한다.
- 다음 프로젝트에 범용적으로 재사용할 수 있어야 한다.
- 사용자는 개발자이므로 git·CI·코드의 기술적 복잡도는 제약이 아니다.

## AI에게 위임한 것

- 어떤 매체를 쓸지. 단 품질 기준을 만족하는 범위 안에서다.
- 페이지 디자인과 데이터 구조.
- 국내 항목의 분야 배분. **고정 비율 없이 그 주의 중요도순으로 고른다**는 결정이 내려져 있다.

## 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 발행 시점 | 월요일 오전 8시 (KST) | ISO 주가 완전히 닫힌 직후이며, 금요일 미국 시장·발표까지 포함된다 |
| 주 경계 | ISO 8601 주 (월~일) | 표준 주차 표기를 쓰면 제목의 시점 모호성이 자동으로 사라진다 |
| 국내 배분 | 고정 비율 없이 중요도순 | 개수를 채우는 것보다 신뢰가 우선이라는 기준과 일치한다 |
| 저장소 공개 | public | 무료 계정에서 GitHub Pages는 public 레포에서만 발행된다 |
| 발행 방식 | Pages 소스를 GitHub Actions 로 | 빌드를 직접 소유해 실패 로그를 전부 볼 수 있고, 워크플로와 스크립트는 다른 호스팅으로 그대로 옮길 수 있다 |

## 아직 열린 항목

- 분기·반기 단위 인사이트를 둘 것인가.
- 월간·연간 인사이트를 어떤 방식으로 생성할 것인가.
- 콘텐츠 원본에서 사이트를 생성하는 빌드 단계를 어떤 도구로 둘 것인가. 첫 주간호를 만들어 본 뒤 정한다.
