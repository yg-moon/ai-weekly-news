# ROUTINE

이 문서는 **매주 무엇을 어떻게 실행하는가**의 유일한 기준이다. Routine 트리거에 저장된 프롬프트는 이 문서를 가리키는 포인터일 뿐이며, 둘이 어긋나면 이 문서가 맞다.

## 이 문서가 SSOT인 이유

- Routine 프롬프트는 Anthropic 서버에 저장되어 git 밖에 있다. 거기에 사양을 쓰면 버전 관리도 되돌리기도 불가능하다.
- 그래서 프롬프트는 짧은 포인터로 고정하고, 실제 사양은 전부 이 파일에 둔다.
- 절차를 바꿀 때는 이 파일만 고친다. 트리거는 거의 건드릴 일이 없다.

## 트리거 설정

`create_trigger` 도구로 등록한다. 파라미터는 다음과 같다.

| 필드 | 값 |
|---|---|
| `name` | `ai-weekly-news 주간 발행` |
| `cron_expression` | `0 23 * * 0` |
| `create_new_session_on_fire` | `true` |
| `notifications` | `{"push": true}` |
| `initiation` | `human_request` |

- cron은 UTC로 해석되며 `0 23 * * 0`은 **월요일 08:00 KST**다. 일광절약시간이 없는 KST라 연중 고정이다.
- 매 발행마다 새 세션을 쓴다. 주간호끼리 문맥이 섞이지 않아야 하고, 푸시 알림 설정도 새 세션 방식에서만 받는다.

등록할 프롬프트 전문은 아래와 같다. 이 블록 외의 내용을 프롬프트에 넣지 않는다.

```
yg-moon/ai-weekly-news 의 주간 브리핑을 발행한다.

1. add_repo 로 yg-moon/ai-weekly-news 를 세션에 붙이고 클론한다.
2. docs/ROUTINE.md 를 처음부터 끝까지 읽는다.
3. 그 문서의 절차를 그대로 수행한다. 사양의 기준은 이 프롬프트가 아니라 ROUTINE.md 다.
4. 판단이 필요한 지점은 docs/INTENT.md 의 원칙을 따른다.
```

## 실행 절차

### 1. 대상 주 확정

발행 시점은 KST 월요일 아침이고, 대상은 **직전에 완결된 주**다. 컨테이너 시간대가 UTC일 수 있으므로 반드시 KST로 계산한다.

```bash
MON=$(TZ=Asia/Seoul date -d '7 days ago' '+%Y-%m-%d')   # 대상 주 월요일
SUN=$(TZ=Asia/Seoul date -d '1 day ago'  '+%Y-%m-%d')   # 대상 주 일요일
WEEK=$(TZ=Asia/Seoul date -d "$MON" '+%G-W%V')          # 예: 2026-W37
```

- `%G-W%V`는 ISO 연도와 주차라 연말·연초 경계에서도 어긋나지 않는다. `%Y`는 쓰지 않는다.
- 수동 실행 등으로 월요일이 아닌 날 돌릴 때는 대상 주를 명시적으로 지정받는다.

### 2. 분야별 수집

세 분야를 **각각 따로** 수행한다. 한 번의 검색으로 15건을 뽑지 않는다.

| 분야 | 건수 | 범위 |
|---|---|---|
| 국내 | 5 | 고정 비율 없이 그 주의 중요도순. 산업·경제와 정치·사회를 미리 배분하지 않는다 |
| 해외 | 5 | 국내 항목과 중복되지 않는 국제 사안 |
| AI | 5 | 국내·해외 어느 쪽이든 무방하며 분야 자체로 묶는다 |

선별 기준은 다음 순서로 적용한다.

- 복수의 공신력 있는 매체가 함께 보도했는가.
- 그 주에 실제로 벌어진 일인가. 예고나 전망은 사안이 아니다.
- 한 주가 지나도 의미가 남는가. 1년 뒤 되짚을 가치가 있는지 본다.
- 이미 실은 항목과 중복되지 않는가.

### 3. 항목 작성

각 항목은 다음 셋을 모두 갖춘다. 하나라도 못 쓰면 그 항목은 뺀다.

- **무슨 일이 있었는지** — 사실 관계를 두세 문장으로.
- **왜 중요한지** — 맥락과 파급. 헤드라인 반복이 아니어야 한다.
- **출처** — 매체명과 링크. 복수 매체를 확인했다면 둘 이상 단다.

### 4. 채우지 못했을 때

- 기준을 만족하는 사안이 5건에 못 미치면 **채우지 않는다**.
- 해당 분야 말미에 몇 건을 실었고 왜 5건이 아닌지 한 문장으로 밝힌다.
- 억지로 채운 5건보다 정직한 3건이 낫다.

### 5. 콘텐츠 파일 작성

`content/weekly/<WEEK>.md` 로 저장한다. 예: `content/weekly/2026-W37.md`

```markdown
---
week: 2026-W37
period_start: 2026-09-07
period_end: 2026-09-13
published: 2026-09-14
counts: { domestic: 5, world: 5, ai: 5 }
---
```

- 사이트 HTML이 아니라 이 마크다운이 원본이다. 월간·연간 인사이트는 이 파일들을 읽어서 만들기 때문에, HTML만 남기면 나중에 파싱해야 한다.
- 프론트매터의 `counts`는 실제로 실은 건수를 적는다. 5가 아니어도 그대로 적는다.

### 6. 사이트 반영

- 주간호 페이지는 `site/week/<WEEK>/index.html` 에 둔다. URL은 `/week/2026-W37/` 이 된다.
- `site/index.html` 의 아카이브 목록에 새 주차를 최신순 맨 위로 추가한다.
- 기존 주차 페이지는 절대 수정하지 않는다. 발행된 주간호는 덮어쓰지 않는다.

### 7. 커밋과 발행

- 커밋 메시지는 `Publish <WEEK> (<MON>~<SUN>)` 형식으로 한다.
- `main` 에 푸시하면 Actions 워크플로가 `site/` 를 Pages로 배포한다.
- 배포 성공까지 확인한 뒤 종료한다. 실패하면 원인을 남기고 알린다.

## 제목과 경로 규약

| 대상 | 형식 | 예 |
|---|---|---|
| 콘텐츠 파일 | `content/weekly/<ISO주차>.md` | `content/weekly/2026-W37.md` |
| 사이트 경로 | `/week/<ISO주차>/` | `/week/2026-W37/` |
| 페이지 제목 | `<ISO주차> 주간 브리핑 (<기간>)` | `2026-W37 주간 브리핑 (9월 7일–13일)` |

- ISO 주차를 앞세우면 정렬과 식별이 동시에 해결된다.
- 경로에 줄임말을 쓰지 않는다. 월간·연간을 얹을 때도 `/month/2026-09/`, `/year/2026/` 로 같은 규칙을 따른다.
- "이번 주", "최근" 같은 상대 표기는 제목에도 본문에도 쓰지 않는다.

## 아직 검증되지 않은 것

실제로 한 번 돌려보기 전까지 확정으로 취급하지 않는다.

- 트리거가 띄우는 새 세션에서 `add_repo` 로 이 레포에 접근할 수 있는지.
- 그 세션이 웹 검색으로 지난 주 기사를 충분히 수집할 수 있는지. 수집 가능한 깊이가 이 루틴의 실질적 상한이다.
- 푸시 알림이 실제로 도착하는지.
- `content/` 마크다운에서 `site/` HTML을 생성하는 빌드 단계를 둘지, 세션이 직접 HTML을 쓰게 둘지. 첫 주간호를 만들어 보고 정한다.
