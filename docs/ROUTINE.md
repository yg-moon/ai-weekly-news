# ROUTINE

이 문서는 **매주 무엇을 어떻게 실행하는가**의 유일한 기준이다. Routine 트리거에 저장된 프롬프트는 이 문서를 가리키는 포인터일 뿐이며, 둘이 어긋나면 이 문서가 맞다.

## 왜 이 문서가 기준인가

- Routine 프롬프트는 Anthropic 서버에 저장되어 git 밖에 있다. 거기에 사양을 쓰면 버전 관리도 되돌리기도 안 된다.
- 프롬프트는 짧은 포인터로 고정하고 실제 사양은 전부 이 파일에 둔다. 절차를 바꿀 때는 이 파일만 고친다.

## 트리거 설정

`create_trigger` 도구로 등록한다.

| 필드 | 값 |
|---|---|
| `name` | `ai-weekly-news 주간 발행` |
| `cron_expression` | `0 23 * * 0` |
| `create_new_session_on_fire` | `true` |
| `notifications` | `{"push": true}` |
| `initiation` | `human_request` |

- cron은 UTC로 해석되며 `0 23 * * 0`은 **월요일 08:00 KST**다. KST는 일광절약시간이 없어 연중 고정이다.
- 매 발행마다 새 세션을 쓴다. 주간호끼리 문맥이 섞이지 않고, 푸시 알림은 새 세션 방식에서만 받는다.

등록할 프롬프트 전문이다. 이 블록 외의 내용을 프롬프트에 넣지 않는다.

```
yg-moon/ai-weekly-news 의 주간 브리핑을 발행한다.

1. add_repo 로 yg-moon/ai-weekly-news 를 세션에 붙이고 클론한다.
2. docs/ROUTINE.md 를 처음부터 끝까지 읽는다.
3. 그 문서의 절차를 그대로 수행한다. 사양의 기준은 이 프롬프트가 아니라 ROUTINE.md 다.
4. 판단이 필요한 지점은 docs/INTENT.md 의 원칙을 따른다.
```

## 실행 절차

### 1. 대상 주 확정

대상은 **직전에 완결된 ISO 주(월~일)**다. 컨테이너가 UTC라도 반드시 KST로 계산한다. 아래 명령은 어느 요일에 실행해도 맞다. 일요일 밤에 돌리면 아직 안 끝난 이번 주가 아니라 지난주가 나온다.

```bash
SUN=$(TZ=Asia/Seoul date -d 'last sunday' '+%Y-%m-%d')    # 대상 주 일요일
MON=$(TZ=Asia/Seoul date -d "$SUN - 6 days" '+%Y-%m-%d')  # 대상 주 월요일
WEEK=$(date -d "$MON" '+%G-W%V')                            # 예: 2026-W36
```

- `%G-W%V`는 ISO 연도·주차라 연말 경계에서도 어긋나지 않는다(2027-01-04 실행 → `2026-W53`). `%Y`를 쓰지 않는다.
- `content/week/<WEEK>.md`가 이미 있으면 그 주는 발행된 것이다. 덮어쓰지 말고 종료한다.

### 2. 수집 환경의 제약

실제로 확인된 것들이다. 이 제약 안에서 최선을 다하고 제약을 감추지 않는다.

- **기사 본문을 읽을 수 없다.** 컨테이너의 네트워크 정책이 GitHub·패키지 저장소 외의 아웃바운드를 차단해 `WebFetch`는 뉴스 사이트에서 전부 실패한다. 쓸 수 있는 것은 `WebSearch`가 돌려주는 링크 목록과 요약뿐이다.
- **검색 요약을 사실로 취급하지 않는다.** 요약은 소형 모델이 합성한 것이라 수치와 날짜가 틀릴 수 있다. 같은 사실이 둘 이상의 결과에서 일치할 때만 쓴다.
- **주요 매체 다수가 검색 자체를 차단한다.** `allowed_domains`에 넣으면 `not accessible to our user agent` 오류가 나며 그 호출 전체가 실패한다. 아래 매체 목록의 '차단' 열을 먼저 본다.
- **날짜는 링크 경로로 확인한다.** 대부분의 매체 URL에 `2026/09/01` 형식의 날짜가 있다. 대상 주 밖의 기사는 배경 설명에만 쓰고 사안의 근거로 삼지 않는다.

### 3. 매체 목록

`WebSearch`의 `allowed_domains`에 넣어 분야별로 검색한다. 검색 엔진이 미국 기준이라 국내 뉴스는 영문판이 훨씬 잘 잡힌다.

| 분야 | 접근 가능 | 차단됨 (넣으면 오류) |
|---|---|---|
| 국내 | `koreaherald.com` `koreatimes.co.kr` `koreajoongangdaily.joins.com` `en.sedaily.com` `en.yna.co.kr` `news.sbs.co.kr` | `yna.co.kr` `chosun.com` `joongang.co.kr` `donga.com` `hani.co.kr` `mk.co.kr` |
| 해외 | `npr.org` `cnn.com` `aljazeera.com` `washingtonpost.com` `france24.com` `axios.com` `cnbc.com` | `reuters.com` `apnews.com` `bbc.com` `nytimes.com` `wsj.com` `ft.com` `theguardian.com` `economist.com` `politico.com` `dw.com` |
| AI | `cnbc.com` `techcrunch.com` `axios.com` `bloomberg.com` `venturebeat.com` 와 1차 출처 `openai.com` `blog.google` `huggingface.co` | `theverge.com` `arstechnica.com` `wired.com` |

- 목록에 없는 매체를 시도해 보는 것은 좋다. 새로 확인되면 이 표를 갱신한다.
- 한 분야에 최소 두 번 검색한다. 하나는 대상 주의 날짜를 넣은 넓은 질의, 하나는 후보 사안을 확인하는 좁은 질의다.

### 4. 분야별 수집

세 분야를 **각각 따로** 수행한다. 한 번의 검색으로 15건을 뽑지 않는다.

| 분야 | 건수 | 범위 |
|---|---|---|
| 국내 | 5 | 고정 비율 없이 그 주의 중요도순. 산업·경제와 정치·사회를 미리 배분하지 않는다 |
| 해외 | 5 | 국내 항목과 겹치지 않는 국제 사안 |
| AI | 5 | 국내·해외 무관. 분야 자체로 묶는다 |

선별 기준을 이 순서로 적용한다.

- 둘 이상의 접근 가능한 매체가 보도했는가. 한 매체의 기사가 여러 개여도 한 매체다.
- 그 주에 실제로 벌어진 일인가. 예고·전망·분석 기사는 사안이 아니다. 주 밖의 사안은 그 주에 후속 조치가 있을 때만 그 후속을 싣는다.
- 한 주가 지나도 의미가 남는가. 1년 뒤 되짚을 가치가 있는지 본다.
- 이미 실은 항목과 겹치지 않는가.

### 5. 항목 작성

각 항목은 다음 셋을 모두 갖춘다. 하나라도 못 쓰면 그 항목은 뺀다.

- **무슨 일** — 사실 관계를 서너 문장으로. 수치는 출처가 말한 그대로 쓰고, 출처끼리 다르면 어느 쪽인지 밝힌다.
- **왜 중요한가** — 맥락과 파급. 헤드라인의 반복이 아니어야 한다. 출처에 없는 해석은 그 주의 다른 사안과의 연결로만 한다.
- **출처** — 매체명과 링크, 둘 이상. 대상 주 밖의 기사를 근거로 쓸 때는 괄호로 이유를 밝힌다.

### 6. 채우지 못했을 때

- 기준을 만족하는 사안이 5건에 못 미치면 **채우지 않는다**.
- 해당 분야 끝에 인용 블록(`>`)으로 몇 건을 실었고 어떤 후보가 왜 탈락했는지 한두 문장으로 밝힌다.
- 억지로 채운 5건보다 정직한 3건이 낫다.

### 7. 콘텐츠 파일 작성

`content/week/<WEEK>.md`에 저장한다. 이 마크다운이 원본이고 HTML은 여기서 생성된다. 월간·연간 인사이트도 이 파일들을 읽어 만든다.

```markdown
---
week: 2026-W36
period_start: 2026-08-31
period_end: 2026-09-06
published: 2026-09-14
domestic: 4
world: 5
ai: 5
---

## 국내

### 1. 제목 — 부제 (9월 1일 화)

- **무슨 일**: …
- **왜 중요한가**: …
- **출처**: [매체 — 구분](url) · [매체](url)

> (5건 미만일 때) 국내는 4건을 실었다. …

## 해외

…

## AI

(분야 전체를 관통하는 맥락이 있으면 첫 항목 앞에 한 문단)

### 1. …
```

- 프론트매터는 평면 `key: value`만 쓴다. `domestic`·`world`·`ai`는 실제로 실은 건수다.
- 제목 끝에 날짜와 요일을 괄호로 넣는다. "이번 주", "최근" 같은 상대 표기는 어디에도 쓰지 않는다.
- 섹션 제목은 `## 국내`, `## 해외`, `## AI` 셋으로 고정한다.

### 8. 빌드와 발행

```bash
npm ci && npm run build      # content/week/*.md → site/
git add content/week/<WEEK>.md
git commit -m "Publish <WEEK> (<MON>~<SUN>)"
git push origin main
```

- `site/`는 빌드 산출물이라 커밋하지 않는다. Actions 워크플로가 푸시마다 같은 빌드를 돌려 Pages에 배포한다.
- 푸시 뒤 `actions_list`로 워크플로 성공을 확인하고 종료한다. 실패하면 로그를 읽고 원인을 남긴다.
- 발행된 주간호의 본문은 고치지 않는다. 오류는 파일 끝에 `## 정정` 절을 두고 날짜와 함께 덧붙인다.

## 제목과 경로 규약

| 대상 | 형식 | 예 |
|---|---|---|
| 콘텐츠 파일 | `content/week/<ISO주차>.md` | `content/week/2026-W36.md` |
| 사이트 경로 | `/week/<ISO주차>/` | `/week/2026-W36/` |
| 페이지 제목 | `<ISO주차> 주간 브리핑 (<기간>)` | `2026-W36 주간 브리핑 (8월 31일–9월 6일)` |

- 경로에 줄임말을 쓰지 않는다. 월간·연간을 얹을 때도 `content/month/`와 `/month/2026-09/`, `content/year/`와 `/year/2026/`으로 같은 규칙을 따른다.

## 아직 검증되지 않은 것

- 트리거가 띄우는 새 세션에서 `add_repo`로 이 레포에 접근할 수 있는지.
- 푸시 알림이 실제로 도착하는지.
- 환경의 네트워크 정책을 열면 `WebFetch`로 본문을 읽을 수 있는지, 그때 크롤러 차단 매체도 열리는지.
